# TripoSG 尺寸恢复与本地失败恢复

2026-08-31，网站任务 `AUTO-20260831-161428-4118F92A`（40 mm 小鼠）在 `m2_submit` 失败。

## 根因

原始 TripoSG GLB 尚未封闭，尺寸恢复函数却调用了要求完整实体的平底修复。目标高度已经能算到 40 mm，实际异常为 `M2_FLAT_BASE_GATE_BLOCK / foundation_requires_one_valid_connected_solid`，被外层包装成“未能恢复目标物理尺寸”。网格还没进入后续 M2 修复就提前退出了。

另外，请求先落盘、完成记录后落盘的防重复提交机制，会使这种本地后处理失败再次触发 `M2_SUBMISSION_STATE_INCOMPLETE`。

## 通用修复

- `export_glb_at_target_height` 只统一缩放并平移到 Z=0，不改变拓扑，不做平底验收，也不声称模型已可打印。按照已有 glTF +Y / 打印 +Z 坐标约定计算高度，保留场景变换。
- `scale_mesh_to_target_height` 保留修复后严格归一化与平底检查。网格修复、最终刀路、姿态和可拆支撑检查都未移除。
- 新 GLB 在临时路径导出并回读核验高度，通过后才替换目标。禁止覆盖源文件；失败保留已有输出。
- TripoSG 明确提供 `recover_local_submission`：持久化请求完全匹配、原始 GLB 和参考图存在时，仅恢复本地后处理，不执行 Worker。缓存缺失、请求改变或模型无效时仍停止。
- 其他 Provider 未提供这种本地恢复能力时，继续拒绝盲目重复提交。没有删请求记录来绕过提交保护。
